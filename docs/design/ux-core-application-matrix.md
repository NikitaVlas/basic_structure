# UX Core application matrix

Use this matrix to choose a starting set of patterns. It is a heuristic, not a substitute for user research or validation.

| UI / product task | Start with these patterns | Main question |
|---|---|---|
| Landing page / positioning | Framing effect, Anchoring effect, Availability heuristics, Context effect, Von Restorff effect | Is the value understood and framed honestly? |
| Onboarding | Serial-position effect, Primacy effect, Peak-end rule, Curse of knowledge, Empathy gap | Can a new user reach first value without overload? |
| Registration / login | Omission bias, Reactance, Processing difficulty effect, Unit bias, Loss aversion | Is the commitment clear, safe, and reversible? |
| Forms | Recognition over recall, Cue-dependent forgetting, Ambiguity effect, Information bias, Law of triviality | Does the form ask only what is necessary at the right time? |
| Checkout / payment | Anchoring effect, Framing effect, Mental accounting, Loss aversion, Decoy effect | Are cost and tradeoffs transparent without pressure? |
| Pricing | Anchoring effect, Contrast effect, Decoy effect, Less-is-better effect, Money illusion | Can users compare options without deceptive manipulation? |
| Dashboard | Attentional bias, Von Restorff effect, Serial-position effect, Information bias, Magical Number 7±2 | What deserves attention first, and what can wait? |
| Search / filtering | Availability heuristics, Frequency illusion, Confirmation bias, Clustering illusion, Information bias | Does the interface help users find rather than confirm guesses? |
| Empty state | Context effect, Picture superiority effect, Self-reference effect, Empathy gap | Does the empty state explain the next useful action? |
| Loading / progress | Peak-end rule, Zeigarnik-like unfinished-task pressure, Planning fallacy, Processing difficulty effect | Is progress meaningful and expectation realistic? |
| Error handling | Negativity bias, Omission bias, Empathy gap, Curse of knowledge, Reactance | Does the error explain recovery without blame or panic? |
| Notifications | Attentional bias, Negativity bias, Availability heuristics, Reactance, Unit bias | Is the interruption necessary, timely, and controllable? |
| Confirmation / destructive action | Loss aversion, Omission bias, Endowment effect, Reactance | Does the user understand consequences and have a safe exit? |
| Social proof / testimonials | Bandwagon effect, Authority bias, Halo effect, Anecdotal evidence, Social desirability bias | Is evidence relevant, verifiable, and not overstated? |
| Recommendations | Automation bias, Authority bias, Confirmation bias, Illusory correlation, Overconfidence effect | Does the system support judgment instead of replacing it? |
| AI assistant | Automation bias, Authority bias, Illusion of control, Curse of knowledge, Overconfidence effect | Are capability, uncertainty, and user control visible? |
| Collaboration / team features | In-group favoritism, Out-group homogeneity, Consensus bias, Social desirability bias, Reactance | Does the design support disagreement and psychological safety? |
| Personalization | Self-reference effect, Barnum effect, Illusion of transparency, Spotlight effect | Is personalization useful without pretending to know too much? |
| Gamification / retention | Hyperbolic discounting, Loss aversion, Endowment effect, Escalation of commitment, Reactance | Is engagement valuable or coercive? |
| Migration / redesign | Conservatism, Status quo bias, Endowment effect, Not invented here, Backfire effect | What will users resist losing, and why? |
| Content / documentation | Curse of knowledge, Processing difficulty effect, Illusory truth effect, Serial recall, Context effect | Can users scan, understand, and act on the content? |
| Analytics / experimentation | Base rate fallacy, Insensitivity to sample size, Anecdotal evidence, Survival bias, Illusion of validity | Are conclusions supported by enough representative evidence? |

## Selection rule

Choose three to seven starting patterns. For each one, document the observed user problem, the proposed interface decision, the ethical boundary, and how the decision will be validated. Do not add a pattern merely because it sounds relevant.
