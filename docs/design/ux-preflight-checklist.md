# UX pre-flight checklist

Run this checklist before considering a UI task complete.

## Intent

- [ ] Primary user and job-to-be-done are explicit.
- [ ] Page or feature promise fits in one sentence.
- [ ] Primary user task and success metric are defined.
- [ ] One primary CTA is obvious.

## Clarity

- [ ] A first-time user can explain the purpose within five seconds.
- [ ] Labels use plain, concrete language.
- [ ] The hierarchy works when scanning, not only when reading linearly.
- [ ] The interface does not require unnecessary memory.
- [ ] Advanced complexity is progressively disclosed.

## Behavioral review

- [ ] Relevant UX Core patterns were selected intentionally.
- [ ] Every selected pattern is connected to a real user problem.
- [ ] The application is labeled source-backed, adapted, or hypothesis.
- [ ] Defaults are safe and reversible.
- [ ] Social proof and metrics have relevant context.
- [ ] No fake urgency, fake scarcity, hidden cost, confirmshaming, or forced continuity exists.
- [ ] The user's preferred choice is not made artificially harder.

## States and recovery

- [ ] Loading state exists.
- [ ] Empty state exists.
- [ ] Validation and error states explain recovery.
- [ ] Success state confirms the result.
- [ ] Retry, undo, cancel, back, or edit exists where risk requires it.
- [ ] Disabled states explain why and how to proceed.

## Accessibility and responsive behavior

- [ ] Keyboard navigation and visible focus work.
- [ ] Labels, roles, and semantic structure are meaningful.
- [ ] Contrast is sufficient and color is not the only signal.
- [ ] Touch targets are usable.
- [ ] The primary task works on mobile.
- [ ] Content remains understandable at zoom and narrow widths.

## Validation

- [ ] The highest-risk assumption has a validation method.
- [ ] Analytics or qualitative feedback can detect success and failure.
- [ ] Unvalidated assumptions are recorded rather than presented as facts.
- [ ] The final review prioritizes comprehension and task completion before decoration.
